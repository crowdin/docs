Die Crowdin Apps JS ist eine JavaScript-Bibliothek, die die Kommunikation zwischen Ihrer App und der Crowdin-Benutzeroberfläche ermöglicht. Da alle Crowdin Apps in einem isolierten `\<iframe>` ausgeführt werden, sind sie isoliert und können nicht direkt auf den Inhalt oder Code der Crowdin-Hauptseite zugreifen.

Diese Bibliothek löst dieses Problem, indem sie eine sichere Cross-Window-Messaging-Brücke (`postMessage()`) bereitstellt. Nach dem Einbinden der Bibliothek steht dir ein globales **`AP`**-Objekt (App Project) zur Verfügung. Dieses Objekt ist Ihr zentraler Einstiegspunkt zum Aufrufen von Methoden (wie `AP.getContext()`) und zum Abonnieren von Ereignissen (wie `AP.events.on()`).

<Aside>
  Serverless-Apps greifen über das Crowdin Serverless Apps SDK auf diese Methoden zu, das diese Bibliothek kapselt. In einer selbst gehosteten App ruft die von dir bereitgestellte Seite `AP` direkt auf.
</Aside>

## Erste Schritte

Um das `AP`-Objekt zu verwenden, musst du das `iframe.js`-Skript im `\<head>` der HTML-Seite deiner App einbinden.

```html
<script src="https://cdn.crowdin.com/apps/dist/iframe.js"></script>
```

<Aside type="caution">
  Lade die Datei `iframe.js` nicht herunter und hoste sie nicht selbst. Sie muss über die Domain <code class="whitespace-nowrap">https://cdn.crowdin.com/</code> bereitgestellt werden, um die domänenübergreifende Messaging-Brücke aufzubauen. Die Bibliothek funktioniert nicht, wenn du sie von deinem eigenen Server oder auf einer eigenständigen Webseite bereitstellst.
</Aside>

## Globale Aktionen

Globale Aktionen sind in jedem Kontext verfügbar, in dem deine App geladen werden kann (z. B. in einem Modal, im Tab „Tools“ des Projekts oder in der Editor-Seitenleiste). Sie werden alle direkt über das Root-`AP`-Objekt aufgerufen.

### Kontext und Theming

Diese Methoden ermöglichen es deiner App, essenzielle Informationen über ihre Umgebung zu erhalten, wie zum Beispiel das aktuelle Projekt, den Benutzer und das aktive UI-Theme.

#### AP.getContext(callback) {#get-context}

Ruf ein `ContextDataObject` ab, das Schlüsselinformationen über die Umgebung enthält, in der die App aktuell ausgeführt wird (z. B. Projekt-ID, Benutzer und Dateidaten).

<Aside>
  * Der Payload dieser Methode ist dynamisch. Je nachdem, auf welcher Seite deine App geladen wird (z. B. im Editor oder in den Project Tools), kann er unterschiedliche Eigenschaften enthalten.
  * Wenn ein Wert nicht verfügbar ist, wird sein Schlüssel im Kontextobjekt weggelassen, statt auf `null` gesetzt zu werden.
  * Die Angaben zu `user`, `project` und `permissions` sind nicht Bestandteil des von <a href="#get-jwt-token">AP.getJwtToken</a> zurückgegebenen JWT-Tokens und stehen der App daher nur im Browser zur Verfügung.
</Aside>

**Beispiel:**

```js
AP.getContext(function(contextData) {
  if (contextData) {
    console.log("Current project ID:", contextData.project_id);
    if(contextData.editor) {
      console.log("Current file name:", contextData.editor.fileData.name);
    }
  }
});
```

#### AP.getPageState(callback) {#get-page-state}

Ruft ein `PageStateObject` mit einer Momentaufnahme des aktuellen Editor-Zustands ab: alles, was `AP.getContext()` zurückgibt, sowie der aktuelle String, die Stringliste, Übersetzungen, Filter und die Dateiauswahl. Verwende es, wenn deine App mehrere Zustände gleichzeitig benötigt, anstatt separate `AP.editor.get*`-Aufrufe aneinanderzureihen.

<Aside>
  Diese Methode ist nur im Editor verfügbar. Der Callback wird ausgeführt, sobald das Laden der Stringliste abgeschlossen ist.
</Aside>

**Beispiel:**

```js
AP.getPageState(function(pageState) {
  if (pageState) {
    console.log("Current string:", pageState.currentString);
    console.log("Current page:", pageState.page);
  }
});
```

### API-Anfragen stellen

Du kannst aus deiner App im Namen des aktuellen Benutzers die Crowdin REST API aufrufen, entweder direkt oder über den offiziellen API-Client.

#### AP.apiRequest(payload, callback) {#api-request}

Deine App kann die Crowdin REST API direkt aus dem iframe aufrufen. Crowdin führt jede Anfrage im Namen des aktuellen Benutzers aus und beschränkt sie auf die im App-Manifest angegebenen Scopes, sodass in deinem Code keine Tokens benötigt werden.

**Beispiel:**

```js
AP.apiRequest(
  { method: "get", path: "projects?limit=25", headers: {} },
  (res) => {
    if (res.status >= 200 && res.status < 300) {
      console.log(res.body.data);
    }
  },
);
```

##### Antwort

Der Callback erhält einen Antwort-Payload mit drei Eigenschaften: `status`, `statusText` und `body`. Crowdin gibt diesen Payload für jede abgeschlossene Anfrage zurück, unabhängig davon, ob sie erfolgreich war. Eine Nicht-2xx-Antwort löst daher keinen Fehler aus. Ein `status` von `0` weist auf einen Netzwerkfehler hin.

Der `body` ist bei JSON-Antworten ein geparster JSON-Wert, bei Textantworten ein String und bei binären Antworten ein `ArrayBuffer`. Er fehlt, wenn die Antwort keinen Body enthält.

##### Datei hochladen

```js
const buffer = await file.arrayBuffer();

AP.apiRequest(
  {
    method: "post",
    path: "storages",
    headers: { "Crowdin-API-FileName": file.name },
    body: buffer,
  },
  (res) => console.log(res.body.data),
);
```

#### Offiziellen API-Client verwenden {#api-client}

Statt `AP.apiRequest` direkt aufzurufen, kannst du den offiziellen [`@crowdin/crowdin-api-client`](https://npmx.dev/package/@crowdin/crowdin-api-client) zusammen mit dem Paket [`@crowdin/apps-api-adapter`](https://npmx.dev/package/@crowdin/apps-api-adapter) verwenden. The adapter implements the client's HTTP layer on top of `AP.apiRequest`, so you get the full typed API surface while every request still runs under the current user's session and manifest scopes.

```bash
npm install @crowdin/apps-api-adapter @crowdin/crowdin-api-client
```

```js
import { AppsApiAdapter } from "@crowdin/apps-api-adapter";
import { Client } from "@crowdin/crowdin-api-client";

const crowdin = new Client(
  { token: "unused" },
  { httpClient: new AppsApiAdapter() },
);

const { data: projects } = await crowdin.projectsGroupsApi.listProjects();

const file = document.querySelector("#file").files[0];
await crowdin.uploadStorageApi.addStorage(file.name, file);
```

<Aside type="note">
  Der `token` ist für den Konstruktor des Clients erforderlich, wird aber nie verwendet. Der Host authentifiziert jede Anfrage mit der Sitzung des aktuellen Benutzers.
</Aside>

* Binäre Uploads akzeptieren ein `Blob`, `File`, `ArrayBuffer` oder typisiertes Array; der Adapter konvertiert diese automatisch.
* Fehlgeschlagene Anfragen werden mit dem üblichen `CrowdinError` / `CrowdinValidationError` des Clients abgewiesen.
* GraphQL ist über die Bridge nicht verfügbar; verfügbar ist nur die REST API (`/api/v2`).

### Navigation

```js
// Redirects to the user's account settings
```

```js
// Redirects to the user's account settings
AP.redirect('/u/user_settings');

// Redirects to a project's Activity tab
AP.redirect('/u/projects/15/activity');

// Redirects to the Store with queryParams
AP.redirect('u/marketplace/apps', {'a': 123});
```

##### Häufig verwendete Filter-IDs

Hier sind einige der häufigsten Standard-Filter-IDs:

* **0**: Alle, nicht übersetzte zuerst
* **2**: Nicht übersetzt
* **3**: Alle anzeigen
* **4**: Genehmigt
* **5**: Übersetzt, nicht genehmigt
* **7**: Mit Kommentaren
* **10**: Durch TM oder MT übersetzt
* **12**: Erweiterter Filter
* **30**: Durch TM übersetzt
* **31**: Durch MT übersetzt

<Aside type="caution">

#### AP.editor.getCustomFilter(callback) {#get-custom-filter}

Ruft ein Objekt ab, das den aktuellen Zustand des „Erweiterten Filters“ darstellt.

**Beispiel:**

```js
AP.editor.getCustomFilter(function(customFilter) {
  if (customFilter) {
    console.log("Current advanced filter settings:", customFilter);
    console.log("Filtering by translation status:", customFilter.translations);
  }
});
```

##### Parameter

<table>
  <tbody>
    <tr>
      <td><code class="whitespace-nowrap">callback</code></td>
      <td>
        <p><strong>Typ:</strong> <code>function</code></p>
        <p><strong>Erforderlich:</strong> ja</p>
        <p><strong>Beschreibung:</strong> Eine Callback-Funktion, die die Antwort verarbeitet. Sie erhält ein <code>CustomFilterObject</code> oder <code>null</code>.</p>
      </td>
    </tr>
  </tbody>
</table>

##### Beispiel für den Response-Payload

```json

  "translations": "untranslated",
  "labels": [123, 456],
  "label_match_rule": "any",
  "comments": "have_comments",
  "croql_expression": "",
  "ai_query": ""
}
```

#### AP.editor.registerContextMenuAction(action, callback) {#register-context-menu-action}

Registriert einen benutzerdefinierten Eintrag im Kontextmenü des Editors (dem Menü, das per Rechtsklick angezeigt wird).

Du musst das `action`-Objekt definieren; der `callback` gibt dasselbe Objekt zurück, ergänzt um eine `eventSubscriptionId`. You then use `AP.events.on` to listen for clicks on that ID.

```js
// 1. Define and register the context menu item
AP.editor.registerContextMenuAction({

  // 2. Listen for clicks on this specific item
  AP.events.on(action.eventSubscriptionId, function() {
    console.log(`'${action.name}' was clicked!`);
    AP.editor.noticeMessage("Custom action triggered!");
  });
});
```

## Ereignisverarbeitung

Mit diesen Methoden kann deine App auf Ereignisse reagieren, die innerhalb der Crowdin-Benutzeroberfläche auftreten (z. B. wenn ein Benutzer einen String ändert oder eine Übersetzung speichert), und eigene benutzerdefinierte Ereignisse auslösen. They are all called via the `AP.events` object.

<ReadMore>
  Weitere Informationen findest du unter [Unterstützte Ereignisse](#supported-events).
</ReadMore>

#### AP.events.on(eventName, callback) {#events-on}

Abonniert einen Listener für ein Ereignis. Dies ist die wichtigste Methode, um sowohl auf Crowdin-UI-Ereignisse (z. B. `string.change`) als auch auf benutzerdefinierte interne Ereignisse zu reagieren, die von deiner App oder der Bibliothek ausgelöst werden.

**Beispiel:**

```js
// Listen for the 'string.change' event from Crowdin
AP.events.on('string.change', function(stringData) {
  console.log("User switched to string ID:", stringData.id);
});
```

      <td>
        <p><strong>Typ:</strong> <code>string</code></p>
        <p><strong>Erforderlich:</strong> Ja</p>
        <p><strong>Beschreibung:</strong> Der Name des Ereignisses, auf das gewartet werden soll (z. B. <code>string.change</code>).
        Siehe den Abschnitt <a href="#supported-events">Unterstützte Ereignisse</a> für eine vollständige Liste.</p>
