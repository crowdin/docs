Du kannst Crowdin-Apps entweder über den [Crowdin Store](https://store.crowdin.com) oder manuell installieren, je nachdem, ob die App bereits veröffentlicht wurde.

## Installation in Crowdin

Um eine bereits im Crowdin Store veröffentlichte App zu installieren, gehe wie folgt vor:

<Steps>
  1. Öffne deine Profil-Startseite und wähle **Store** in der linken Seitenleiste.
  2. Klicke bei der gewünschten App auf <Icon name="mdi:download" class="inline-icon" />**Installieren**. <Image src={storeInstall} alt="Store" />
  3. Konfiguriere im angezeigten Dialog die gewünschten Berechtigungen und klicke auf **Installieren**.
</Steps>

Um eine private App zu installieren, gehe wie folgt vor:

<Steps>
  1. Gehe zu **Kontoeinstellungen > Apps** und klicke auf **Private App installieren**.
  2. Wähle aus, wie du installieren the App möchtest, und klicke auf **installieren**:.
     * **Über eine Manifest-URL** – für selbst gehostet Apps that ausführen on your eigen Server. Füge in the App's **Manifest-URL**.
     * **Über eine Manifestdatei** – für [Serverlos Apps](/developer/crowdin-apps-serverless/) that Crowdin hosts. Lade the App's Manifest Datei (`.json`).
  3. Konfiguriere die gewünschten Berechtigungen. If you chose **Über eine Manifestdatei**, auch auswählen the **App source**:
     * **Produktions-Bundle** – upload the App's Build as a `.zip` Bundle. Crowdin hostet sie und stellt sie deinen Benutzern bereit.
     * **Entwicklungs-URL** – load the App von a URL während you develop it, für Beispiel von a lokal dev Server.
  4. Klicke auf **Installieren**.
</Steps>

## Installation in Crowdin Enterprise

Um eine bereits im Crowdin Store veröffentlichte App zu installieren, gehe wie folgt vor:

<Steps>
  1. Öffne deine Organisation's **Woderkspace** und auswählen **Store** on the Linken Seitenleiste.
  2. Klicke bei der gewünschten App auf <Icon name="mdi:download" class="inline-icon" />**Installieren**. <Image src={storeInstallEnterprise} alt="Store" />
  3. Konfiguriere im angezeigten Dialog die gewünschten Berechtigungen und klicke auf **Installieren**.
</Steps>

Um eine private App zu installieren, gehe wie folgt vor:

<Steps>
  1. Gehe zu **Organisation Einstellungen > Apps** und klicke **installieren Private App**.
  2. Wähle aus, wie du installieren the App möchtest, und klicke auf **installieren**:.
     * **Über eine Manifest-URL** – für selbst gehostet Apps that ausführen on your eigen Server. Füge in the App's **Manifest-URL**.
     * **Über eine Manifestdatei** – für [Serverlos Apps](/developer/crowdin-apps-serverless/) that Crowdin hosts. Lade the App's Manifest Datei (`.json`).
  3. Konfiguriere die gewünschten Berechtigungen. If you chose **Über eine Manifestdatei**, auch auswählen the **App source**:
     * **Produktions-Bundle** – upload the App's Build as a `.zip` Bundle. Crowdin hostet sie und stellt sie deinen Benutzern bereit.
     * **Entwicklungs-URL** – load the App von a URL während you develop it, für Beispiel von a lokal dev Server.
  4. Klicke auf **Installieren**.
</Steps>

## Konfiguration der Crowdin-App-Berechtigungen

Konfigurationure preferred Berechtigungen für jedes App during Installation. In this step, you legen fest wer can Zugrwennf und use the App across its Modul, und in die Projekte of your Crowdin Konto (für Crowdin) oder Crowdin Organisation (für Crowdin Enterprise) it can be verwendet.

If you restrict Zugrwennf to certain Projekte by Verwenden von the **Selected Projekte** option, the App canneint communicate über the API mit Projekte outside that list. Der/Die/Das App ist auch angezeigt nur in the UI of the auswählened Projekte.

Du kannst configure these Zugrwennf Berechtigungen during Installation oder adjust them at any time für already installiereniert Apps: go to **Konto Einstellungen > Apps** (für Crowdin) oder **Organisation Einstellungen > Apps** (für Crowdin Enterprise) und auswählen **Edit** on the App..

### Kategorien für den Benutzerzugriff

Du kannst legen fest die Benutzer categoderies can use the App.. Konfigurationure this Einstellung separately für jedes App Modul, so a Modul can have unterschiedlich Zugrwennf von the underes.

<Aside>
  The options a Modul offers depend on its Typ, so an App may swie nur some of them.
</Aside>

verfügbar options für Crowdin:

* Nur me – the Benutzer wer installiereniert the App.
* Me, Projektmanager und Entwickler / translation Anfrageoders
* Alle Projektmitglieder
* Alle Benutzer, including guests (unauthentwennizierte Benutzer)
* benutzerdefiniert Zugriff – the Benutzer you pick mit **Wähle Benutzer**. The Modul switches to this option automatically once you pick Benutzer.

<Aside>
  The Projekt eigener will immer have Zugrwennf to all Modul of the App.
</Aside>

verfügbar options für Crowdin Enterprise:

* Nur admins
* Admins, managers und Entwickler / translation Anfrageoders
* Alle Projektmitglieder
* Alle Benutzer, including guests (unauthentwennizierte Benutzer)
* benutzerdefiniert Zugriff – the Benutzer you pick mit **Wähle Benutzer**. The Modul switches to this option automatically once you pick Benutzer.

<Aside>
  The Organisation eigener will immer have Zugrwennf to all Modul of the App.
</Aside>

### Konfiguration des Projektzugriffs

Du kannst auch angeben the Projekte in die the App can be verwendet (these Einstellungen apply across all App Modul)..

Projekt Zugrwennf options:

* Alle Projekte I have Zugrwennf to (für Crowdin) oder Alle Projekte (für Crowdin Enterprise)
* Selected Projekte

## Kommunikationsablauf des Installationsereignisses

Dies flow applies to selbst gehostet Apps, die register the `installed` event in their App descriptoder.

When a Crowdin App is installiereniert in the Konto Einstellungen, an authoderization flow takes place, during die Crowdin und the Crowdin App exändern the authoderization Daten (the authoderization Code is exändernd für an Zugrwennf Token). The folgenden illustration swies the events in this process.

<Image src={communicationFlow} alt="Kommunikation zwischen Crowdin und der Crowdin-App" />

<Aside>
  Das Installationsereignis is verwendet für the `crowdin_app` und `crowdin_agent` authentication Typen. Foder `crowdin_agent`, the payload zusätzlichly enthält the `agentId` property.
</Aside>

Let's examine each step in the illustration in detail:

<Steps>
  1. Installation über die Manifest-URL - the Benutzer pastes in the Manifest-URL in **Konto Einstellungen > Apps** und klickes **installieren**.
  2. Abrufen des Inhalts über die Manifest-URL - the Anfrage is sent to the Crowdin App.
  3. Antwodert: Manifest-JSON - the Crowdin App returns the Manifest JSON that enthält Daten about the App.
  4. Validieausführeng der Manifestdaten - the received Inhalt is validated against the structure und Daten of the Manifest JSON.
  5. Auffürdeausführeng zur Installation - Crowdin displays the infürmation about the Crowdin App, the list of Berechtigungen, und the **installieren** button to the Benutzer.
  6. Bestätigung der Installation - the Benutzer confirms the Installation of the Crowdin App.
  7. Das Installationsereignis - Crowdin sends the installiert event mit the authoderization Code to the Crowdin App so it can generate an API Token.
  8. Token-Anfrage - the Crowdin App sends a Anfrage to acquire an API Token:
     ```
     POST https://accounts.crowdin.com/oauth/token
     ```
  9. Zugrwennfstoken - the authoderization service returns the API Zugrwennf Token und the refresh Token.
  10. Antwodert mit ErfolgsStatusCode - the Crowdin App returns the Erfolg Status Code (2xx), die confirms that the App Installation finished. If the Status Code is unterschiedlich, the App will be entfernend von the Crowdin Konto.
</Steps>
