Mit dem Modul zur Verarbeitung der Übersetzungszuordnung kannst du Crowdins Standardmechanismus zur Zuordnung überschreiben, wenn du Übersetzungen für Nicht-Schlüssel-Wert-Dateien (z. B. HTML oder MD) hochlädst.

Standardmäßig ordnet Crowdin hochgeladene Übersetzungen automatisch den vorhandenen Source-Strings zu. Wenn du dieses Modul in deiner Crowdin-App verwendest, kannst du diesen Prozess abfangen und deine eigene Zuordnungslogik anwenden, beispielsweise mithilfe eines Zuordnungsdienstes eines Drittanbieters. Damit hast du die volle Kontrolle darüber, wie Übersetzungen bei komplexen Dokumentformaten den entsprechenden Source-Strings zugeordnet werden.

<Aside>
  Dieses Modul ist *nur* für [Nicht-Schlüssel-Wert-Dateiformate](/uploading-translations/#text-and-html-based-formats) wie HTML, Markdown (MD) und andere vorgesehen.
</Aside>

## Zugriff

Du kannst Zugriff auf dieses Modul für eine der folgenden Benutzerkategorien gewähren:

Für Crowdin:

* Nur ich (also der Projektinhaber)
* Ich, Projektmanager und Entwickler
* Ausgewählte Benutzer

Für Crowdin Enterprise:

* Nur Organisationsadministratoren
* Organisationsadministratoren, Projektmanager und Entwickler
* Ausgewählte Benutzer

## Struktur

```json title="manifest.json"
{
  "modules": {
    "file-translations-alignment": [
      {
        "key": "your-translations-alignment-module-key",
        "url": "/translations-alignment",
        "signaturePatterns": {
          "fileName": "^.+\.html$",
          "fileContent": "<html.*>"
        }
      }
    ]
  }
}
```

## Kommunikation zwischen der App zur Verarbeitung der Übersetzungszuordnung und Crowdin

Beim Hochladen einer Übersetzungsdatei für ein Nicht-Schlüssel-Wert-Format erkennt das System anhand des Parameters `signaturePatterns` ein geeignetes Modul zur Verarbeitung der Übersetzungszuordnung. Crowdin sendet anschließend eine HTTP-Anfrage an die URL der App (`$baseUrl`. `$url`).

Diese Anfrage enthält zwei Hauptarrays: `sourceStrings` (aus dem Projekt) und `translationStrings` (aus der hochgeladenen Übersetzungsdatei geparst). Die Aufgabe der App besteht darin, diese beiden String-Mengen zu verarbeiten, die Zuordnung durchzuführen und eine strukturierte Antwort zurückzugeben, die die Übersetzungen den korrekten IDs der Source-Strings zuordnet.

### Erwartete Antwort der App

Die App muss ihre benutzerdefinierte Zuordnung durchführen und eine Antwort mit einem `translations`-Array zurückgeben. Dieses Array ordnet jeden Übersetzungstext seiner entsprechenden `sourceStringId` zu.

Beispiel für die Nutzlast der Antwort:

```json
// max response payload - 5 MB
// wait timeout - 2 minutes
{
  "data": {
    "translations": [
      {
        "sourceStringId": 1234567,
        "text": "Ласкаво просимо!"
      },
      // other translation mappings...
    ],
    // or use translationsUrl for large payloads
    "translationsUrl": "https://app.example.com/jKe8ujs7a-aligned.ndjson" // new-line delimited json file with aligned translations
  },
  "error": {
    "message": "Optional error message"
  }
}
```
