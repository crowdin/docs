You can install Crowdin Apps either from the [Crowdin Store](https://store.crowdin.com) or manually, depending on whether the app is already published.

## Installation in Crowdin

To install an app that is already published on the Crowdin Store, follow these steps:

<Steps>
  1. Open your profile home page and select **Store** on the left sidebar.
  2. Click <Icon name="mdi:download" class="inline-icon" /> on the card of the needed app.
  3. In the dialog that opens, configure preferred permissions and click **Install**.
</Steps>

To install a private app, follow these steps:

<Steps>
  1. Go to **Account Settings > Apps** and click **Install Private App**.
  2. Select how you want to install the app:
      * **From an app file**: For [serverless apps](/developer/crowdin-apps-serverless/) that Crowdin hosts. Upload the app file (`.crowdinapp`), which contains the app's manifest and build.
      * **From a manifest URL**: For self-hosted apps that run on your own server. Paste in the app's **Manifest URL** and click **Continue**.
  3. Configure preferred permissions. If you're developing a serverless app, turn on **Development mode** and enter the **URL** of your local dev server on `localhost` or `127.0.0.1`. Crowdin then loads the app from your computer, and only you can use it while development mode is on.
  4. Click **Install**.
</Steps>

## Installation in Crowdin Enterprise

To install an app that is already published on the Crowdin Store, follow these steps:

<Steps>
  1. Open your organization's **Workspace** and select **Store** on the left sidebar.
  2. Click <Icon name="mdi:download" class="inline-icon" /> on the card of the needed app.
  3. In the dialog that opens, configure preferred permissions and click **Install**.
</Steps>

To install a private app, follow these steps:

<Steps>
  1. Go to **Organization Settings > Apps** and click **Install Private App**.
  2. Select how you want to install the app:
      * **From an app file**: For [serverless apps](/developer/crowdin-apps-serverless/) that Crowdin hosts. Upload the app file (`.crowdinapp`), which contains the app's manifest and build.
      * **From a manifest URL**: For self-hosted apps that run on your own server. Paste in the app's **Manifest URL** and click **Continue**.
  3. Configure preferred permissions. If you're developing a serverless app, turn on **Development mode** and enter the **URL** of your local dev server on `localhost` or `127.0.0.1`. Crowdin then loads the app from your computer, and only you can use it while development mode is on.
  4. Click **Install**.
</Steps>

## Updating Apps

How an installed app gets a newer version depends on how it was installed.

### Updating Self-Hosted Apps

Crowdin checks the manifests of self-hosted apps daily. A change waits for an admin when it widens what the app can do: new scopes, new modules that need an access setting or act on their own, or a different server address. Crowdin applies all other changes on its own. While a change waits, the app shows **Update available** in the apps list, admins see a banner with a **Review** button on the app's pages, and the account owner (for Crowdin) or organization admins (for Crowdin Enterprise) get a notification (**App Updates** in the notification settings).

To review and apply the update, follow these steps:

<Steps>
  1. Go to **Account Settings > Apps** (for Crowdin) or **Organization Settings > Apps** (for Crowdin Enterprise) and select **Edit** on the app.
  2. Review the changes, marked **New**, **Removed**, or **Changed**, and set access for any new modules.
  3. Click **Update**.
</Steps>

To apply a new authentication type, uninstall the app and install it again.

<Aside type="caution">
  Uninstalling an app may permanently delete the data the app stores, such as its configurations and connections, because the app receives the [uninstall event](/developer/crowdin-apps-app-descriptor/#uninstall-event-payload). Installing the app again doesn't restore any data it deletes.
</Aside>

### Updating Serverless Apps

To update a serverless app to a newer version, upload its new app file:

<Steps>
  1. Go to **Account Settings > Apps** (for Crowdin) or **Organization Settings > Apps** (for Crowdin Enterprise) and select **Edit** on the app.
  2. In the **App file** section, click **Update file** (or **Upload file** if the app has no app file yet) and upload the new app file (`.crowdinapp`).
  3. Review the changes and click **Save**.
</Steps>

Saving replaces the app's build and applies the manifest from the file. If the app name in the file differs from the installed app's name, a warning shows both names before you save, because saving gives the installed app the name, access, modules, and build from the file. An update keeps the **Development mode** setting, and while development mode is on, Crowdin loads the app from its URL instead of the app file. You can turn development mode on or off on the same screen.

When an app installed from an app file has the same name as the file you're installing, the dialog warns that the file adds a second copy. To update the installed app instead, click **Update the installed app instead**.

To get the file of an app installed from an app file, for example to share the app, select **Download** on the app.

## Crowdin Apps Permission Configuration

Configure preferred permissions for each app during installation. In this step, you define who can access and use the app across its modules, and in which projects of your Crowdin account (for Crowdin) or Crowdin organization (for Crowdin Enterprise) it can be used.

If you restrict access to certain projects by using the **Selected projects** option, the app cannot communicate via the API with projects outside that list. The app is also displayed only in the UI of the selected projects.

You can configure these access permissions during installation or adjust them at any time for already installed apps: go to **Account Settings > Apps** (for Crowdin) or **Organization Settings > Apps** (for Crowdin Enterprise) and select **Edit** on the app.

### User Access Categories

You can define which user categories can use the app. Configure this setting separately for each app module, so a module can have different access from the others.

<Aside>
  The options a module offers depend on its type, so an app may show only some of them.
</Aside>

Available options for Crowdin:

* Only me &ndash; the user who installed the app.
* Me, project managers and developers / translation requestors
* All project members
* All users, including guests (unauthenticated users)
* Custom Access &ndash; the users you pick with **Select users**. The module switches to this option automatically once you pick users.

In Crowdin, users other than the installer decide whether the app can access Crowdin on their behalf when they use its modules.

<ReadMore>
  Read more about [App access](/account-settings/#app-access).
</ReadMore>

Available options for Crowdin Enterprise:

* Only admins
* Admins, managers and developers / translation requestors
* All project members
* All users, including guests (unauthenticated users)
* Custom Access &ndash; the users you pick with **Select users**. The module switches to this option automatically once you pick users.

### Project Access Configuration

You can also specify the projects in which the app can be used (these settings apply across all app modules).

Project access options:

* All projects I have access to (for Crowdin) or All projects (for Crowdin Enterprise)
* Selected projects

### Apps That Use a Bot

Some apps work in projects through their own bot, a user that Crowdin creates for the app when you install it. The installation dialog shows this bot under **Will perform action as:**. The projects the bot is a member of are the projects the app works in, so these apps skip the project access options.

To add the bot as a manager to all existing projects, keep **Assign bot as a manager to all existing projects** selected when you install the app. To change the bot's permissions later, use the project's **Members** tab or the **Managers** page (for Crowdin) or **Users** page (for Crowdin Enterprise).

## Installed Event Communication Flow

This flow applies to self-hosted apps, which register the `installed` event in their app descriptor.

When a Crowdin App is installed in the Account Settings, an authorization flow takes place, during which Crowdin and the Crowdin App exchange the authorization data (the app exchanges the credentials from the Installed event for an access token). The following illustration shows the events in this process.

<Image src={communicationFlow} alt="Communication between Crowdin and Crowdin App" />

<Aside>
  Crowdin sends the Installed event to apps with the `authorization_code`, `crowdin_app`, `crowdin_agent`, and `crowdin_app_with_code` (Crowdin Enterprise only) authentication types. It sends the event again when the app's permissions or its owner change. For `crowdin_agent`, the payload additionally contains the `agentId` property, and for `authorization_code` and `crowdin_app_with_code`, the `code` property.
</Aside>

Let's examine each step in the illustration in detail:

<Steps>
  1. Installation of the Manifest URL - the user pastes in the Manifest URL in **Account Settings > Apps** and clicks **Continue**.
  2. Fetching content from the Manifest URL - the request is sent to the Crowdin App.
  3. Response: manifest JSON - the Crowdin App returns the Manifest JSON that contains data about the app.
  4. Manifest Data Validation - the received content is validated against the structure and data of the Manifest JSON.
  5. Prompt to install - Crowdin displays the information about the Crowdin App, the list of permissions, and the **Install** button to the user.
  6. Confirmation of the installation - the user confirms the installation of the Crowdin App.
  7. The Installed event - Crowdin sends the Installed event with the credentials the Crowdin App needs to get an API token.
  8. Token request - the Crowdin App sends a request to acquire an API token:
      ```
      POST https://accounts.crowdin.com/oauth/token
      ```
  9. Access Token - the authorization service returns the API access token and the refresh token.
  10. Response: success code - the Crowdin App returns the success status code (2xx), which confirms that the app installation finished. If the status code is different, Crowdin removes the app from the Crowdin account.
</Steps>

**Token request parameters (step 8):**

An app with the `authorization_code` type exchanges the `code` from the Installed event for a token in the [authorization code flow](/developer/authorizing-oauth-apps/#exchange-the-code-for-an-access-token). Apps with the other types send the following parameters:
