使用此模块添加新自定义文件格式的支持。 Crowdin 将源文件解析委托给具有自定义文件格式模块的应用。翻译完成后，Crowdin 会将源文件和包含翻译的字符串数组传递给自定义文件格式应用程序，以便生成翻译文件。

## 访问权限

您可以将此模块的访问权限授予以下用户类别之一：

对于 Crowdin：

* 仅限我自己（即项目所有者）
* 所有项目成员
* 选定用户

对于 Crowdin 企业版：

* 仅限组织管理员
* 组织项目中的所有用户
* 选定用户

## 结构

```json title="manifest.json"
{
  "modules": {
    "custom-file-format": [
      {
        "key": "your-module-key-type-xyz",
        "type": "type-xyz",
        "url": "/process",
        "multilingual": true,
        "customSrxSupported": true,
        "signaturePatterns": {
          "fileName": "^.+\.xyz$",
          "fileContent": "<properties>\s*<property\s+name=.*value=.*/>"
        }
      }
    ]
  }
}
```

## 自定义文件格式应用与 Crowdin 之间的通信

在初始文件导入时，Crowdin 使用 `signaturePatterns` 或 `type` 参数检测自定义文件格式，并向应用的 URL（`$baseUrl . 发送 HTTP 请求。 $url`）发送 HTTP 请求以进行进一步处理。然后应用处理文件并响应 Crowdin。与自定义文件格式应用程序之间的请求和响应具有两分钟超时限制。请求和响应的最大负载大小限制为 5 MB。

## 内容句段

自定义文件格式的内容可以通过两种方式拆分为较小的段：你的应用使用 Crowdin 传递给它的规则自行分段内容，或者 Crowdin 使用其自己的解析器之一对内容进行分段。当只有你的应用能解析内容时，在应用中分段；当字符串包含 Crowdin 已支持的格式（如 HTML 或 Markdown）的内容时，留给 Crowdin 解析器处理。

### 在你的应用中对内容进行分段

在模块配置中将 `customSrxSupported` 属性设置为 `true`。然后可以为该模块处理的文件设置[分段规则（SRX 2.0）](/custom-segmentation/)，例如通过[添加文件](/developer/api/v2/#operation/api.projects.files.post)和[更新文件](/developer/api/v2/#operation/api.projects.files.put) API 方法的 `importOptions.srxStorageId` 参数。

Crowdin 在 `parse-file` 和 `build-file` 请求的 `customSrxContents` 参数中传递为文件定义的规则内容。应用自行进行分段：

* 对于 `parse-file` 任务，应用按这些规则拆分文本，并将每个段作为单独的字符串返回，带有自己的 `identifier`（如果应用生成文件的 HTML 预览，则还有自己的 `previewId`）。
* 对于 `build-file` 任务，应用接收这些段及其翻译，并在生成翻译文件时将它们重新连接。

如果没有为文件定义规则，`customSrxContents` 为 `null`。

翻译上传也使用 `parse-file` 任务，因此在解析翻译文件时返回相同的每段标识符。否则上传的翻译将无法与现有段匹配。

### 使用 Crowdin 解析器对内容进行分段

将字符串的 [`attributes.crowdinType`](#strings-array-structure) 属性设置为其内容的格式。然后 Crowdin 会像解析该格式的文件一样解析此类字符串，因此内容会按照该项目对该格式的设置或该格式的默认分段进行分段。

每个段在项目中成为单独的字符串。对于 `build-file` 任务，Crowdin 将翻译合并回原始字符串，因此应用收到的字符串与文件解析期间返回的字符串相同。

带复数的字符串不会被重新解析，在基于字符串的项目中该属性没有效果。

<Aside title="限制">
  每个段都算作单独的字符串，因此分段文件会更快达到 5 MB 的请求和响应载荷限制。
</Aside>

## 文件 HTML 预览

HTML 预览在编辑器中渲染[文件的所见即所得视图](/online-editor/#wysiwyg-file-preview)。将每个可翻译字符串包裹在一个同时携带以下两者的元素中：

* `id="string_preview_id_{previewId}"`，其中 `{previewId}` 与 `parse-file` 响应中对应字符串的 `previewId` 匹配。使用双引号并使值完全匹配。
* `class="crowdin_phrase"`，以便编辑器可以在预览中高亮字符串并就地编辑。没有此 class，字符串仅在从字符串列表中选择时高亮，预览中的就地编辑不起作用。

如果应用将字符串拆分为多个段，请为每个段提供自己的 `previewId` 和预览中的元素。如果多个段共享一个 `previewId`，只有最后一个链接到该元素。

HTML 预览仅在源文件导入期间生成。上传翻译（包括多语言上传）时不会生成它，应用传递带复数的字符串时也不会显示它。

文件 HTML 预览示例：

```html
<html lang="en">
  <head>
    <title>Optional Title</title>
    <style>
      table, th, td {
        border: 1px solid #aaa;
      }
    </style>
  </head>
  <body>
    <h1 style="text-align: center">HTML preview of the file</h1>
    <table style="width: 100%">
      <tr>
        <th>Key:</th>
        <th>Text:</th>
      </tr>
      <tr>
        <td>Key 1</td>
        <td><span id="string_preview_id_1" class="crowdin_phrase">Source Text 1</span></td> <!-- 1 是 strings json 中的 previewId -->
      </tr>
      <tr>
        <td>Key 2</td>
        <td><span id="string_preview_id_2" class="crowdin_phrase">Source Text 2</span></td> <!-- 2 是 strings json 中的 previewId -->
      </tr>
    </table>
  </body>
</html>
```
