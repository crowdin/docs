在项目设置的**导入**部分，您可以配置 Crowdin 应如何处理项目中的占位符、重复字符串和字数统计。

## 源字符串

通过统一占位符和处理重复字符串来提高翻译一致性并简化工作流程。

### 统一占位符

启用此选项可在编辑器中将占位符转换为统一格式（例如，将 Android `%s` 和 iOS `%@` 均显示为 `[%s]`）。这通过使建议在各平台之间完全通用来提高翻译记忆库的效率。

导出时，占位符将转换回原始语法。此功能仅适用于 Android XML、iOS strings、iOS XLIFF 和 Apple Strings Catalog。

### 重复的字符串

您可以通过使用相同的翻译来翻译所有重复项并对翻译人员隐藏这些实例来节省时间。这可能会影响准确性。

Crowdin 的本地化流程基于将源字符串翻译为所定义的目标语言。源字符串以本地化文件形式上传到系统。在 Crowdin 中首次上传或添加（对于 CSV 和其他支持[字符串编辑](/enterprise/string-management/#string-editing)的格式）的每个唯一源字符串都被视为主字符串。所有其他与主字符串相同，但上传或创建时间较晚的字符串都被视为重复字符串。

<Aside>
  在[基于字符串](/enterprise/creating-project/#string-based-project)的项目中，重复字符串使用\*\*在版本分支内显示（常规检测）\*\*选项进行管理，该选项默认启用且无法更改。
</Aside>

<Aside>
  在[传入项目](/enterprise/for-vendors/#duplicate-strings)中，重复字符串选项以及主字符串与其重复项之间的链接会遵循客户的项目设置。
</Aside>

#### 重复字符串管理

如果你的项目包含重复的字符串，你可以选择系统应如何处理它们。可用选项结合了三个维度：检测依据、可见性和译文共享。

| 选项                 | 检测依据                | 编辑器中的可见性     | 译文共享 |
| ------------------ | ------------------- | ------------ | ---- |
| **显示**             | 常规（源文本）             | 重复项保持可见      | 否    |
| **显示，但自动翻译它们**     | 常规（源文本）             | 重复项保持可见      | 是    |
| **在版本分支内显示（常规检测）** | 常规 + 分支路径范围         | 重复项在版本分支之间隐藏 | 是    |
| **在版本分支内显示（严格检测）** | 严格（源文本 + 键）+ 分支路径范围 | 重复项在版本分支之间隐藏 | 是    |
| **隐藏（常规检测）**       | 常规（源文本）             | 重复项已隐藏       | 是    |
| **隐藏（严格检测）**       | 严格（源文本 + 键）         | 重复项已隐藏       | 是    |

<Aside>
  仅当重复项没有自己的译文时，才会从主字符串共享译文。
</Aside>

检测依据决定什么算作重复项：

* **常规重复检测** &ndash; 比较字符串时，Crowdin 仅考虑源文本。
* **严格重复检测** &ndash; 比较字符串时，Crowdin 同时考虑字符串标识符（键）和源文本。

<Aside type="tip">
  如果您的源文件包含具有明显标识符（键）的字符串，则最好使用**严格**版本的重复字符串选项。在其他情况下，请随意使用**常规**版本。
</Aside>

#### 译文共享的工作原理

启用译文共享后，只要重复项没有自己的译文，就会继承主字符串的译文。

如果为重复项（即使是隐藏的重复项）保存了唯一的译文，它将停止继承主译文，转而使用自己的译文。

如果该唯一译文后来被移除，共享会自动恢复，重复项将再次继承主译文。

#### 共享译文何时不适用

共享译文在以下情况下不适用：

* 选择了**显示**（自动共享已禁用）。
* 重复项已有自己的唯一译文。
* 在**在版本分支内显示**模式下，字符串超出用于重复检测的分支或路径匹配范围。

#### 显示所有重复项

选择**显示 – 译者将分别翻译每个实例**选项后，所有重复字符串将对译者可见。每个重复项都需要单独翻译。

💡 **使用案例**：非常适用于相同单词可能根据语境具有多种含义的项目。

#### 显示但自动翻译重复项

选择**显示，但自动翻译它们**选项后，所有重复字符串都会显示，并自动从主字符串继承译文。这样，翻译人员就可以在必要时检查并重新翻译重复的字符串。

💡 **使用案例**：如果您想节省时间但仍需要审核自动翻译，那么这种方法非常有效。

为了更好地说明**显示，但自动翻译**选项的工作原理，请考虑以下五字符串 JSON 文件：两个字符串是唯一的，三个字符串具有相同的源文本。

```json
{
    "hello": "您好",
    "welcome": "欢迎！",
    "save1": "保存",
    "save2": "保存",
    "save3": "保存"
}
```

导入此文件后，系统会将这些相同字符串中的第一个（`"save1": "Save"`）指定为主字符串，并标记为“主”，而后续两个相同字符串（`"save2": "Save"` 和 `"save3": "Save"`）被指定为该主字符串的重复项，并标记为“重复”。

将**重复字符串**选项设置为**显示，但自动翻译它们**后，系统会保持所有五个字符串对译者可见，并启用自动译文共享。

让我们考虑以下情景：

* *先翻译主字符串* &ndash; 系统会立即将主字符串的译文共享给其重复项。结果，所有三个相同的字符串（主字符串及其两个重复字符串）都显示有译文。译者仍然可以审阅共享译文，并为任何特定重复项替换为唯一译文。这样做会仅覆盖该字符串的共享译文，从而实现精确的、符合上下文的翻译，而不会影响其他重复项。
* *先翻译其中一个重复项* &ndash; 系统不会将重复项的译文共享给主字符串或其他重复项。因此，一个重复字符串会显示译文，而主字符串和另一个重复项则保持未翻译状态，直到主字符串被翻译（然后剩余的重复项将继承该译文），或者它们被单独翻译。

#### 在版本分支内显示

选择**在版本分支内显示**选项（常规或严格检测）后，只有最初上传到系统的主字符串可供翻译。所有重复字符串将自动继承主字符串的译文，并在所有[版本分支](/enterprise/version-management/)中隐藏。

这里有几点需要注意：

* 系统始终检查整个分支中字符串的路径。例如，即使不同版本分支（`branch1` 和 `branch2`）中的字符串相同，但它们的路径不同（branch1 - `/localization/android.xml` 和 branch2 - `/localization/apps/android.xml`），它们也不会被识别为重复项。
* 此选项仅适用于位于具有相同格式的文件中的字符串。例如，如果 `android.xml` 和 `ios.strings` 文件中有相同的字符串，它不会被识别为重复项。

💡 **使用案例**：非常适合具有各种版本分支的持续性项目。允许翻译员在不同的分支中使用唯一的字符串。

#### 隐藏所有重复项

选择**隐藏**选项（常规或严格检测）后，系统会在所有文件中发现重复字符串。只有最初上传的主字符串才可见并且应被翻译。隐藏的重复字符串将自动从相应的主字符串继承译文。

💡 **使用案例**：适用于范围较窄的项目，在这些项目中，所有重复字符串都共享相同的上下文。

## 单词和字符计数

配置你希望 Crowdin Enterprise 如何统计项目中的单词和字符。具体来说，此设置决定 HTML 标签应作为常规单词计数还是忽略。默认情况下，Crowdin Enterprise 会将大多数支持格式中的 HTML 标签视为常规单词，但以下格式除外：HTML、Front Matter HTML、HAML、MD、Front Matter MD、XML、WEBXML、IDML、XLIFF、XLIFF 2.0、ADOC、DOCX 和 DITA。

* **自动**（默认）&ndash; 根据默认的格式特定规则统计单词和字符。根据源文件格式，HTML 标签要么作为常规单词计数，要么被跳过。
* **统计标签** &ndash; 始终考虑标签。所有 HTML 标签都将作为常规单词计数。
* **跳过标签** &ndash; 始终跳过标签。 HTML 标签将不被计数。

<Aside>
  更改选项后，只有新上传的单词将按照新设置进行计数。强烈建议在将源文件上传到项目之前配置此设置。
</Aside>
